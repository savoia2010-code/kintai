# タイムライン照合（案A）仕様

Google マップのタイムライン書き出し（iPhone 版 JSON）を月に1回ほどブラウザで取り込み、記録と照らし合わせる。
主な記録は宣言（入力した記録）のままとし、タイムラインは確認と補完にだけ使う。

## 前提（データ形式）

- トップレベルは区間の配列。種類は `visit` / `activity` / `timelinePath` / `timelineMemory`。値はすべて文字列。
- 座標は `"geo:緯度,経度"`。
- 時刻の表記が混在している（visit・activity は `+09:00`、timelinePath は UTC の `Z`）。日時として解釈してから日本時間（+9h 固定）に揃える。

## 守ること

- 生データはブラウザ内でだけ処理する。localStorage・GAS・外部へ送らない（再読み込みで消える）。
- 座標は画面に表示しない。会社の場所は端末内（`kintai_v1_office`）にだけ保存する。
- 確定している記録は自動で上書きしない。候補として表示するだけにする。
- GAS・mergeRemote・同期の経路は変えない。

## 1. 取り込み

- ファイルを選ぶと、その場で JSON を読む。
- 使うのは対象月（締め日で区切った期間、前月26日〜当月25日）の `visit` だけ。

## 2. 会社の場所の登録（初回のみ）

- 平日 8〜20 時に滞在した場所を、場所ID（無い場合は近さ）でまとめて候補にする。
- 200m 以内の場所IDは1つの候補にまとめる（実データで、同じ敷地が 75〜167m 離れた3つの場所IDに分かれていた）。会社の場所はまとめた場所IDすべてと中心座標で持つ。
- 夜（0〜5時）に1時間以上いた日が3割以上ある場所は自宅とみなして外す（リモートワークのため、外さないと自宅が1位になる）。
- 順位はデータの最終日から1年以内の滞在で付ける（昔の職場を上位に出さない）。
- 候補は「滞在日数・1日あたりの平均時間・最初と最後の日付」で示す（座標は出さない）。
- 選んだ場所を `kintai_v1_office` に保存する。バックアップには、接続設定と同じチェック（「接続設定と会社の場所も書き出す」）を入れたときだけ含める。

## 3. 日ごとの集計

- 30分以上の滞在だけを数える。確からしさの値でのしきい値は設けない。
- 同じ日の滞在が複数あれば1日分にまとめ、次を出す：最初の到着、最後の出発、会社にいた合計時間、途中の外出時間。

## 4. 照合の結果

「一覧」タブの上に照合パネルを置く。対象月はレポートタブと共用（一覧そのものは月で絞らないため、パネル内に月の選択を置く）。

| 状況 | 表示 |
|---|---|
| 「出社」の記録があり、会社にいた | 始業・終業の差（30分単位で差がなければ ✓） |
| 「リモート」の記録だが、会社にいた | 候補：場所を「出社」または「混在」に |
| 「出社」の記録だが、会社にいなかった | 注意 |
| 記録がなく、会社にいた | 候補：出勤（週末は休日出勤）・出社で新しく記録 |
| 「年休」「欠勤」なのに、会社にいた | 注意 |
| その日のタイムラインが無い | 判定できない（灰色） |

- 「混在」の日は、会社にいた時間が始業〜終業の中に収まっているかだけを確認する。
- リモートの時間はタイムラインからは判断しない（宣言が正）。
- 候補の時刻は、今の入力と同じく 30 分単位の切り捨て（`snapToHalfHour`）にする。
- 昼の外出は休憩に自動で入れない。「外出 ○分」と横に表示するだけにする（休憩の既定 1:00 は変えない）。

## 5. 反映

- 候補ごとの「反映」ボタンで、その内容を入力フォームに入れる。ユーザーが確認して保存すると、いつもどおり未送信の一覧に入り、同期される。
- 一括での反映は作らない。

## 実装

- 照合ロジック: `timeline.js`（DOM・通信なし。ブラウザでは `window.KintaiTimeline`）
- テスト: `node --test tests/*.test.js`（架空の座標だけを使う）
- 画面: `index.html` の `TimelinePanel`
